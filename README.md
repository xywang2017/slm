# A small language model, from scratch

A readable PyTorch decoder-only Transformer for learning the full training and inference pipeline. Defaults: 2 layers, 4 attention heads, width 64, context 64 bytes, about 140k parameters. This is an educational language model, not a useful assistant or a pretrained model.

Decoder-only Transformers are a common choice for modern generative language models. They predict the next token from previous tokens. Encoder-decoder Transformers remain useful for input-to-output tasks such as translation; an encoder reads the input and a decoder generates the output using cross-attention. Here, decoder-only keeps the entire learning path small and visible.

## Run on CPU

Python 3.12+ is required. From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt --index-url https://download.pytorch.org/whl/cpu
python -m unittest discover -s tests -v
python -m slm.train
python -m slm.generate --prompt 'The little robot' --tokens 200
```

The included story was written for this project. No dataset or pretrained model download is needed. Default training is 300 optimizer steps on CPU. Checkpoints go to ignored `checkpoints/tiny.pt`; they are not committed. For a compatible CUDA PyTorch installation, use the official PyTorch installer and pass `--device cuda` to both commands.

Train with your own UTF-8 text:

```bash
python -m slm.train --data path/to/book.txt --steps 3000 --context 128 --width 128 --layers 4 --heads 4 --output checkpoints/book.pt
python -m slm.generate --checkpoint checkpoints/book.pt --prompt 'Once upon a time' --temperature 0.8 --top-k 40
```

Each of the contiguous 90% training and 10% validation splits must have more bytes than the context length. More steps on the tiny story mainly encourage memorization. Larger, diverse datasets are needed for useful generalization. A GPU helps as models and datasets grow.

## Follow the training process

1. **Tokenize:** text becomes UTF-8 bytes (IDs 0–255). This supports any text without a vocabulary-building stage. Tokens here are bytes, not words; generated bytes can be invalid UTF-8, displayed as replacement characters.
2. **Build examples:** sample a context window `x`; its target `y` is shifted one byte to the right. For `hello`, the pairs are `hell -> ello`. Every position predicts its next byte.
3. **Embed:** add learned token embeddings and position embeddings, producing `[batch, time, width]` vectors.
4. **Apply layers:** each block uses layer normalization, multi-head self-attention, a residual addition, then another normalization, a feed-forward network with GELU, and another residual addition. The causal mask sets future attention scores to negative infinity before softmax. See `slm/model.py` for the explicit operations.
5. **Score tokens:** the final layer produces `[batch, time, 256]` logits. Cross-entropy compares these scores against the shifted targets. Training computes all positions in parallel while the mask enforces causality.
6. **Learn:** backpropagate the loss, clip gradient norm to 1, and update weights with AdamW. Dropout is active during training and disabled for evaluation.
7. **Validate and save:** print losses on fixed held-out and training windows, then save model configuration and weights. Validation has no gradient updates. The checkpoint is for inference; optimizer/RNG state and exact training resume are not implemented.

Lower loss means higher probability assigned to the correct next byte. An untrained model starts near `ln(256) = 5.55` loss, with variation from random initialization. Held-out loss is a useful signal, but this tiny single-story split is not a reliable generalization benchmark. Evaluation uses one fixed batch per split for speed.

## Follow inference

Load configuration and weights, encode the prompt, run the most recent context window through the model, take the last position's logits, divide by temperature, keep the top-k candidates, sample one byte, and append it. Repeat without gradients. Lower temperature sharpens probabilities; top-k=1 gives greedy decoding. There is no end-of-sequence token, so generation stops at the requested byte count.

Generation recomputes the context each step and resets learned positions within a sliding window when context is exceeded. This simple implementation has no KV cache. Many larger modern models use rotary positions, RMSNorm, gated feed-forward layers, and faster attention kernels; the same next-token training objective still applies.

## Code map and checks

- `slm/model.py`: configuration, explicit Q/K/V attention, stacked blocks, loss and sampling.
- `slm/train.py`: data split, random shifted batches, AdamW, evaluation and checkpoint writing.
- `slm/generate.py`: checkpoint loading and text generation.
- `tests/test_model.py`: causal isolation, target alignment, learning on a repeating pattern, checkpoint equivalence, generation across the context boundary and invalid inputs.

Only load checkpoints you trust. Seeds aid reproducibility on the same software/hardware; they do not guarantee identical results across devices or PyTorch versions.
